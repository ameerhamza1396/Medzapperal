# Medzapperal

A high-fidelity, responsive medical apparel storefront prototype built from the supplied product brief.

## Run locally

```bash
npm install
npm run dev
```

## Included

- Editorial home page with original generated hero artwork
- Responsive product catalog with category, color, fabric, search, and sort filters
- Product details with color/size/quantity selection
- Functional cart drawer and persisted dark/light theme
- Responsive admin dashboard concept with metrics, orders, inventory alerts, and product status
- Realistic sample catalog data ready to replace with Supabase queries

## Production setup

### 1. Supabase

1. Create a Supabase project.
2. Open **SQL Editor**, paste and run
   `supabase/migrations/202607170001_initial_store.sql`.
3. In **Authentication → Providers → Email**, keep email/password enabled and
   enable email confirmation.
4. In **Authentication → Email Templates → Confirm signup**, use the contents
   of `supabase/templates/confirm-signup.html`. The important value is
   `{{ .Token }}`—this sends a six-digit OTP instead of a magic-link button.
5. Add your production URL in **Authentication → URL Configuration**.
6. Create your first account through the site, then promote it in SQL:

   ```sql
   update public.profiles
   set role = 'admin'
   where id = 'YOUR_AUTH_USER_UUID';
   ```

Normal login uses email and password. OTP is used to verify a new signup.
Supabase persists and refreshes the user session securely in the browser.

### 2. ImageKit

Create an ImageKit account and collect the public key, private key, and URL
endpoint from **Developer options**. The app uploads directly to ImageKit using
a short-lived signature generated by `/api/imagekit-auth`. This endpoint first
verifies the Supabase access token and the user's `admin` or `staff` role.
The private key is never shipped to the browser.

The admin dashboard includes a protected upload test. Successful uploads return
both the ImageKit URL and `fileId`, ready to store in `product_images`.
`/api/imagekit-delete` provides protected deletion by `fileId`.

### 3. Hosting environment variables

Copy `.env.example` to `.env.local` for local development. In Vercel or
Netlify, add:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`
- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `IMAGEKIT_PUBLIC_KEY`
- `IMAGEKIT_PRIVATE_KEY` (server-only)
- `IMAGEKIT_URL_ENDPOINT`

Apply them to Production, Preview, and Development as appropriate. Never prefix
the ImageKit private key with `VITE_`.

### 4. Deploy on Vercel

Import the repository into Vercel. The included `vercel.json` configures Vite,
SPA routing, production output, and API security headers.

```bash
pnpm install
pnpm build
```

Before launch, set the Supabase **Site URL** to the final Vercel domain and add
any preview domains you intend to use under Redirect URLs.

### 5. Deploy on Netlify

Import the repository into Netlify. The included `netlify.toml` configures:

- Build command: `pnpm run build`
- Publish directory: `dist`
- Netlify Functions for ImageKit auth/delete endpoints
- SPA redirects so shared product URLs and refreshes work

Add the same environment variables listed above in **Site configuration →
Environment variables**. Before launch, add the final Netlify domain and preview
deploy domains to Supabase **Authentication → URL Configuration**.
